Use SM3 pathfinding and physics for supported mob movement, add physical skeleton arrows and Blaze fireballs, let spiders climb walls, and burn exposed zombies and skeletons in daylight. Record typed world-data failures for affected targets while other stage work continues. Reject malformed present state.

World-data and entity failures share the existing frame-state outbox and `drainGameplayEntityStageFaults`, including typed light and block-write failures.

## Public contract changes

Relative to PR base main (18fa7df6), callers must handle the Result and Effect error channels listed below. The inventory follows every export reachable from the package entrypoint and includes inferred declarations. Function-body changes alone are excluded. Referenced-type changes are listed separately from directly changed declarations.

The entrypoint replaces the wildcard export of `src/domain/chunk-window.ts` with named exports `chunkCoordOf`, `chunkCoordsAround`, `openChunkWindow`, `UNREADABLE_BLOCK`, and type `ChunkWindow`. World-data failures now use `EntityStageFault` and `drainGameplayEntityStageFaults(state)`. The separate `GameplayStageFaults` service, its module factory `makeGameplayStageFaults`, layer, state field, occurrence counts, and registration environment requirement are removed. The four pure reason/item-use failure types retain their existing names.

Hosts that drain faults retain state from `makeGameplayFrameStateForOwner` and pass it to `gameplayStages`; `makeGameplayStages` and `gameplayModule` keep their state private.

`applyWeatherState(current, candidate)` becomes `applyWeatherState(candidate)` and returns `Result<WeatherState, "invalid-weather-state">`. `DespawnReason` loses `unmeasurable`. `HostileMobSnapshot.behaviour` becomes optional and excludes explicit undefined. Explosion exposure, hostile-contact/blast difficulty, and right-click range arguments use omission-aware rest tuples. Boat and minecart helpers reject negative and non-finite elapsed time; valid positive time is capped at 0.1 seconds. Spawn planners reject malformed feet positions before simulator repair. The request-fault variant of `EntityStageFault` carries optional `positionKey` for requests without an ID, preserving target-specific deduplication.

For those rest-tuple arguments, omission retains the existing defaults: explosion exposure is 1, hostile difficulty is `normal`, and right-click range is `DEFAULT_BLOCK_REACH`. Explicit `undefined`, `null`, and other invalid values return typed failures. The tuples admit either no argument or one value of the declared type, excluding explicit undefined and null.

`GameplayEntityRosterSchema` restores a JSON-omitted entity `behaviour` key to undefined through `migrateLegacyMissingEntityBehaviour`. For omitted legacy behavior state, `repairMobBehaviour` uses `migrateLegacyMissingCreeperFuse`, `migrateLegacyMissingEndermanFlinch`, `migrateLegacyMissingPrimedTntFuse`, and `migrateLegacyMissingEcosystemMobState`. In `repairEcosystemMobState`, `migrateLegacyEcosystemMobFields` supplies omitted `hasHeadProtection` as false and `burningTicks` as 0.
